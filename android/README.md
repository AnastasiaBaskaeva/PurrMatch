# PurrMatch Android

Первый этап: слои MVVM + Clean Architecture и навигация на Jetpack Compose.
Экраны пустые: только названия и кнопки для проверки переходов. Дизайна,
форм, карточек, сервера и настоящей авторизации пока нет.

## Модули

- `domain` — Kotlin/JVM, контракты и модели без Android. Пока содержит контракт сессии.
- `data` — Kotlin/JVM, реализация `SessionRepository` в памяти, зависит только от `domain`.
- `presentation` — Android library, Compose, типизированные маршруты, ViewModel и компоненты состояний. Зависит только от `domain`.
- `app` — Application, Activity и сборка зависимостей через Hilt. Связывает три слоя.

Android-модули используют встроенный Kotlin AGP 9; обработка Hilt работает через KSP.
Версии библиотек собраны в `gradle/libs.versions.toml`.

## Навигация

При запуске открывается Главная, чтобы можно было сразу проверить каркас приложения.

- Главная → Фильтры → возврат; Главная → Анкета кошки.
- Избранное → Анкета кошки или Публичный профиль автора.
- Профиль → Создание анкеты, Анкета кошки, Настройки, Вход или Регистрация.
- Настройки → Заявка на верификацию; для гостя → Вход, для демосессии → Выход.
- Анкета кошки → Публичный профиль автора → Анкета кошки.
- Вход ↔ Регистрация; «Продолжить (заглушка)» → Главная с очисткой стека авторизации.
- Выход → Вход с удалением основной части из стека.

Три вкладки имеют отдельные графы с сохранением и восстановлением стека.
Нижняя панель показана на корневых экранах вкладок. Вложенные экраны имеют
кнопку «Назад» и поддерживают системный возврат. Авторизация открывается
поверх основной части: возврат сохраняет прежнюю вкладку.
Маршруты используют `@Serializable`; анкета и публичный профиль принимают
только строковые ID. Сейчас для переходов используются ID-заглушки.

`SessionViewModel` получает контракт из `domain` через Hilt и предоставляет
состояние сессии UI. Демосессия хранится только в памяти и сбрасывается при
перезапуске процесса. Это каркас для будущей авторизации, а не проверка аккаунта.

`PlaceholderScreen` и `NavigationAction` — базовые компоненты каркаса.
`ScreenState` и `StateContent` подготовлены для состояний загрузки, пустого
списка, ошибки с повтором и контента; пустые экраны пока их не показывают.

## Требования

- JDK 17 или новее (доступна JBR из Android Studio).
- Android SDK Platform 36 и Build Tools 36.0.0.
- SDK в `ANDROID_HOME` или `local.properties` (`sdk.dir=...`).

Откройте эту папку как проект в Android Studio.

## Сборка и проверки

```sh
./gradlew :app:lintDebug :app:testDebugUnitTest :data:test :app:assembleDebug
```

Проверки приложения выполняются также в Android CI для PR в `android/trunk`.
Исходная ветка PR должна начинаться с `android/`, согласно Branch policy.

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Автоматических тестов пока нет; задачи тестов завершаются с `NO-SOURCE`.

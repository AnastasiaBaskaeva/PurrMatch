# PurrMatch Android

Экраны и библиотека Jetpack Compose компонентов из страницы Figma
[«Ии макет», 264:5](https://www.figma.com/design/X7Kp2gmSu5nTt3mpFwV7d0/neRacov-meet?node-id=264-5).

- `presentation/src/main/.../components`: переиспользуемые компоненты и тема.
- `presentation/src/main/.../auth`, `browse`, `favorites`, `profile`, `filters`, `listing`: все 16 экранов и два состояния свайпа, сгруппированные по функциональности.
- `presentation/src/main/.../App.kt`: точка входа, подключающая зависимости.
- `presentation/src/debug`: Preview всех экранов и каталог компонентов.
- `domain`: Kotlin/JVM, модели, контракты репозиториев и подбор по фильтрам без Android/Compose.
- `data`: Kotlin/JVM, моковые репозитории анкет, профилей, персонального выбора и локальной сессии.
- `app`: приложение для запуска экранов и проверки сценариев на устройстве, Application и сборка зависимостей через Hilt.
- `design/figma`: исходные SVG и соответствие Android-ресурсам.

Доменная анкета содержит `authorId` и список `ListingPhoto` с непрозрачными ссылками,
дату рождения `LocalDate?` (null, если дата неизвестна) и цену `Long` в целых рублях.
Возраст вычисляется из даты рождения; русские подписи даты, возраста и цены формирует
presentation. Профиль хранит фамилию, координаты, отдельный WhatsApp и статус
верификации. История и избранное по-прежнему хранят ID анкет отдельно для каждого
пользователя. Старый сериализованный снимок моков читается с преобразованием дат,
цен и фото. Читаются как отдельные старые/типизированные анкеты, так и wrapper
авторизации с вложенными старыми/типизированными данными. При наличии wrapper
исходные соли и проверочные значения паролей сохраняются; demo fallback применяется
только к снимкам без credentials. Следующая запись атомарно сохраняет типизированные
данные и credentials вместе.

`navigation/PurrMatchApp.kt` подключает настоящие экраны к Navigation 3. Маршруты
анкеты и автора содержат только `listingId` и `authorId`; отсутствующие ID показывают
явное пустое состояние. У каждой вкладки свой сохраняемый стек. ViewModel создаются
в области NavEntry через штатные декораторы сохранения состояния и ViewModelStore;
формы используют `SavedStateHandle` и StateFlow. UI получает значения и callbacks.
После выхода авторизованный стек и его ViewModel удаляются.
Переходы внутри стека сдвигают экраны вперёд и обратно с учётом направления
интерфейса; смена вкладок и подтверждения используют затухание Navigation 3.
Predictive Back сохраняет стандартную анимацию Navigation 3 и поддерживает отмену жеста.
Android-модули используют встроенный Kotlin AGP 9, Hilt обрабатывается через KSP.

Открывайте эту папку в Android Studio. Нужны JDK 17+, Android SDK 37 и
`sdk.dir` в локальном `local.properties` либо `ANDROID_HOME`.

```sh
./gradlew :app:assembleDebug :presentation:assembleRelease
./gradlew :app:lintDebug :presentation:lintDebug :app:testDebugUnitTest :data:test
ANDROID_SERIAL=emulator-5554 ./gradlew :presentation:connectedDebugAndroidTest :app:connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.purrmatch.android/.MainActivity
# Открыть debug-образец конкретного экрана:
adb shell am start -S -n com.purrmatch.android/.MainActivity --es screen home
# Сохранённый каталог компонентов:
adb shell am start -S -n com.purrmatch.android/.MainActivity --es sample catalog
```

Без сессии приложение открывает вход; с сохранённой сессией — основную часть.
Вход проверяет зарегистрированный логин и пароль, регистрация отклоняет занятый
логин и открывает заполнение профиля. Логины чувствительны к регистру; пробелы по
краям удаляются. Пароль регистрации содержит не менее 8 символов. Серверная
авторизация пока не подключена. Репозитории сохраняют профиль, анкеты, фильтры,
избранное и просмотренные ID в приватном каталоге приложения; выбор привязан к ID
пользователя. Новый аккаунт получает пустое избранное и историю.

Локальные демонстрационные аккаунты `anna_cats` и `olga_cats` используют пароль
`purrmatch-demo`. Это публичные mock fixtures, не реальные учётные данные.
Все профили, сохранённые предыдущей версией без паролей, при миграции тоже получают
`purrmatch-demo`: восстановить прежние введённые пароли невозможно. Существующие
профили, анкеты, избранное, история и активная сессия сохраняются. Новые регистрации
получают собственный пароль и случайный ID. Профиль и проверочное значение пароля
записываются атомарно в одном файле; чтение старого формата поддерживается.
Хранятся случайная соль 16 байт и PBKDF2-HMAC-SHA1 (210 000 итераций, 256 бит),
без открытого пароля. Только публичные старые/демонстрационные аккаунты используют
общее заранее вычисленное проверочное значение, чтобы загрузка данных не выполняла
дорогое хеширование. Для каждой новой регистрации соль уникальна. Этот алгоритм [доступен с API 10](https://developer.android.com/reference/javax/crypto/SecretKeyFactory),
включая minSdk 24. Пароли формы остаются только в памяти ViewModel: пересоздание
Activity сохраняет ввод, после смерти процесса пароль нужно ввести снова.
Если аккаунт сохранён, но запись сессии завершилась ошибкой, форма сообщает,
что нужно войти с только что созданными учётными данными.

Навигация, ввод и подтверждения восстанавливаются при пересоздании Activity.
Фотографии выбираются системным Photo Picker, контакты относятся к автору выбранной
анкеты и открываются установленными приложениями. Медиа пока используют индексы
списка выбранных фото хоста: постоянный импорт URI и восстановление собственных
фото между полноценными запусками остаются отдельным этапом.

Избранное сохраняет неактуальные анкеты после удаления автором. Свайпы
переключают карточки, правый добавляет в Избранное. Колода исключает собственные
и удалённые анкеты. История учитывает только завершённые свайпы: открытие деталей
и короткий отменённый жест не убирают карточку. Фильтры применяются к
локальному набору анкет; сброс восстанавливает исходные условия. Back отменяет
черновик фильтров, применение и сброс сохраняют историю просмотра. Формы
прокручиваются, основное действие закреплено снизу, системные панели и
клавиатура учитываются в хосте.

## Debug-образцы

Extras `screen` и `sample`, `Screen`, `SampleApp` и все превью находятся в debug.
Они используют отдельные фикстуры и не изменяют сохранённые данные основного
приложения. В основном графе пустое избранное и отсутствие результатов — состояния
данных, а промежуточный свайп — состояние жеста.

`ScreensTest` проверяет пользовательские сценарии и снимает все 18
состояний при размере 376×803 dp. PNG сохраняются в
`presentation/build/outputs/connected_android_test_additional_output`.
Снимки диалогов включают отдельное окно Android. Рамка телефона и условный
статус-бар Figma служат оформлением макета; на устройстве используются настоящие
системные панели. В размерах и отступах за основу принят контент макета 376×803;
на других размерах области растягиваются, длинный контент прокручивается.

`NavigationTest` проверяет ID анкеты/автора, контакты, Back, сохранение текущей
карточки, отмену фильтров, отсутствующий ID и смену аккаунта. `NavigationMotionTest`
проверяет движение экранов, затухание вкладок, отмену и завершение predictive Back,
возврат из регистрации и закрытие подтверждения. `ActivityRestorationTest`
запускает настоящий Hilt-хост и пересоздаёт Activity на профиле автора, в формах
настроек/анкеты и подтверждении выхода. `:data:test` проверяет повторное чтение
хранилища, разделение аккаунтов и сохранение избранного после удаления анкеты.
